# 视频插件开发文档

Nova Studio 开源版**不内置任何视频上游协议**。视频 tab、任务队列、历史记录、素材上传、
表单渲染都由宿主提供；「向谁发什么请求、怎么轮询、结果在哪、表单长什么样」全部写在插件包里。

一个插件就是一个目录，管理员把它放进服务器的插件文件夹即安装。插件是纯 JSON 数据，
v1 不包含任何可执行代码。

## 插件包长什么样

```
backend/plugins/my-plugin/
  manifest.json     身份、模型清单、申报价、凭据、出网白名单、素材配额
  ui.schema.json    表单描述（宿主用自己的组件渲染，你不写任何前端代码）
  provider.json     上游请求模板 + 轮询规则 + 结果取值路径
  README.md         可选，给用户看的说明
```

三个 JSON 都是必需的，且 `manifest.id` 必须与目录名一致。

目录名以 `.` 或 `_` 开头的会被跳过——想临时停用一个插件，把 `my-plugin` 改名成
`_my-plugin` 即可，不用删。

## 边界：你负责什么，宿主负责什么

**你（插件）只负责**

- 模型清单与申报价
- 表单有哪些字段、字段之间的约束
- 上游请求怎么拼（URL、头、体）
- 上游状态词表、进度字段、结果与错误的取值路径
- 需要访问哪些主机

**宿主负责（你不用管，也管不着）**

- 视频 tab、导航、主题、移动端适配
- 任务表、队列、并发名额、轮询调度、超时判死
- 参考素材落盘、公网地址、TTL 清理、任务删除时连带清理
- 上传进度、失败重试、刷新页面后的对账
- 历史记录、预览、下载、链接失效探测
- 限流、表单渲染、价格显示
- 凭据存储（用户在设置里填，从不入库）

**你拿不到的东西**：数据库、文件系统、`fetch`、`process`、任何 Node 模块。
插件不是代码，所以也没有「插件把服务器搞崩」这种情形。

## 三件必须知道的事

**1. 出网要申报。** `manifest.permissions.hosts` 里没写的主机，宿主会直接拒绝请求，
连内网地址（`127.0.0.1`、`10.*`、`169.254.169.254` 等）一起拦。这不是可以绕过的建议。
这张表只管**插件自己发起的请求**（创建与查询）；产物地址由浏览器直接加载，不必写进来。

**2. 凭据是用户的。** apiKey 与 baseUrl 由用户在「设置 → 插件」里填，存在浏览器
localStorage，提交任务时随请求转发，只在发上游请求那一瞬间替换进模板。
它不入库、不进日志、不在任何返回体里出现。你在模板里写 `{{apiKey}}` 就够了。

**3. 结果必须归一化。** 你在 `provider.poll.result.assets` 里告诉宿主去哪取产物地址，
宿主把它压成统一结构存进历史。所以你的插件被卸载之后，用户的旧记录依然能预览和下载。
这一步做不好，历史记录就会被你的上游细节污染。

---

## 版本兼容

三个 JSON 都要写 `"apiVersion": 1`。宿主拒绝加载 apiVersion 不匹配的插件，
并在「设置 → 插件」里显示原因——不会静默忽略，也不会带着一半字段勉强跑。

`manifest.version` 用语义化版本。历史记录里存了提交时的插件 id 与版本，
所以升级插件不会让旧记录变得无法解释。

## 参考实现

`backend/plugins/ccode-h3/` 是随仓库分发的完整示例（MiniMax H3 系列，8 个模型，
三个档位、四档分辨率、首尾帧、参考图/视频/音频、超分档位强制带图）。
它覆盖了协议里几乎所有特性，遇到不确定的写法先去那里找一遍。
