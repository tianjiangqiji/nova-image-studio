# GPT Image 2.6 原生 GIF / SVG 输出

本文说明当前原生输出流程，并取代[早期适配记录](2026-11-05-gpt-image-2.6-native-output.md)中的 GIF 默认 20 帧和 SVG 聊天接口方案。

## 模型配置

在「设置」中添加 OpenAI 协议的图片模型，选择 GPT Image 2.6 Flare 或 Sunburst 模板，填写自己的 API 地址和密钥。官方模型 ID 分别为 `gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`；已有供应商配置保留实际模型 ID、API 地址和密钥，不自动迁移。

原生输出能力按 OpenAI 协议和实际 `gpt-image-2.6` 系列模型 ID 判断，不依赖用户设置的显示名称。供应商自定义型号是否真正支持 GIF / SVG，仍取决于该供应商的接口和账号权限。

这里使用 OpenAI 兼容 Images API，不使用 ChatGPT 网页私有接口或聊天接口生成 SVG。

## 原生 GIF

1. 打开「动图生成」，选择支持的 2.6 模型。
2. 开启「原生 GIF」，描述主体、动作和循环方式。
3. 设置帧数与每帧时长，提交后直接预览、下载上游返回的动画。

| 参数 | 默认值 | 范围与处理 |
| --- | --- | --- |
| 帧数 `frame_count` | `9` | `2–16` 的整数 |
| 每帧时长 `frame_duration_ms` | `200` 毫秒 | `20–2000` 毫秒的整数，发送时按 `10` 毫秒四舍五入 |

这两项参数随设置和任务保存，并用于重新生成。旧设置中的越界参数回到默认值；新提交的非法参数会明确报错。帧数、每帧尺寸和总动画数量还受上游像素预算限制，参数校验通过不代表上游一定接受所选尺寸。

原生请求使用 `POST /v1/images/generations`，请求体示例：

```json
{
  "model": "gpt-image-2.6-sunburst",
  "prompt": "一只西兰花吉祥物招手，动作连贯，首尾无缝循环",
  "output_format": "gif",
  "n": 1,
  "stream": false,
  "frame_count": 9,
  "frame_duration_ms": 200
}
```

本工作台的原生 GIF 当前只开放文字生成：上传与粘贴参考图入口隐藏，已有参考图不会进入生成或提示词优化请求，服务端也会拒绝参考图和 Markup。原生输出不发送 `partial_images` 或 `output_compression`，不使用网格图、手动切帧或浏览器编码器拼接动画。关闭「原生 GIF」后，原有网格流程仍可使用。

官方 GIF 接口还支持 `/images/edits` 的参考图动画；这不代表本工作台已经开放该入口。

GIF 输出还要求上游为所选模型开放 GIF preview 权限。模型出现在 `/models` 中并不代表该权限已开通；公开接口没有客户端启用开关。若返回 `GIF output is not enabled for this request.`，应用会保留原始原因并提示联系服务商确认当前模型、渠道或项目权限，不自动重复生成或更换模型。

## 原生 SVG

在生图工作台选择支持的模型，开启「原生 SVG 矢量图」，输入文字描述后生成。存在参考图时提交按钮禁用，并提示移除参考图或关闭 SVG；服务端同样拒绝 SVG 图生图、参考图和 Markup 请求。

SVG 与 GIF 一样使用 Images generations 接口，不再调用 `/chat/completions`：

```json
{
  "model": "gpt-image-2.6-sunburst",
  "prompt": "一个绿色蔬菜主题的极简矢量图标，使用清晰的可编辑路径",
  "output_format": "svg",
  "n": 1,
  "stream": false
}
```

SVG 固定单图生成，不发送流式、`partial_images` 或 `output_compression` 参数；不通过本地描摹 PNG 生成矢量文件。上游返回的 `data[0].b64_json` 解码后即为 SVG XML 字节，支持原始格式预览和 `.svg` 下载。官方 SVG 输出是静态矢量内容，不支持脚本、外部资源或内嵌位图。

## 结果格式与验证边界

- 后端依据文件字节识别格式，原样保存 GIF / SVG，并使用对应 MIME 和扩展名提供预览与下载；SVG 响应带 `nosniff` 和 CSP sandbox。
- 任务失败会区分生成请求、结果下载和结果保存阶段；可取得时显示 HTTP 状态、白名单网络错误码和上游 `request-id`。错误在保存前隐藏密钥、凭据字段和 URL，仅保留经过脱敏的错误摘要。网络断开后不会自动重新提交生成，避免重复计费。
- GIF 显示实际帧数。上游返回单帧 GIF、静态 PNG 或其他格式时，保留原始结果并明确提示，不把静态图称作动画，也不将错误格式改名成 `.gif` 或 `.svg`。
- 本次自动化集成检查使用本地模拟上游，覆盖原生请求参数、格式与原始字节保存、错误传播和非法请求拦截；前端测试覆盖参数恢复与提交限制。
- 生产构建在桌面（1365×1000）和手机（390×844）浏览器均已跑通 SVG / GIF 提交、任务完成、预览与下载；下载扩展名正确，文件与模拟上游返回的原始字节完全一致，无页面横向溢出。
- 浏览器同时验证了旧 20 帧设置恢复为 9 帧、17 帧输入禁用提交，以及 25 毫秒按 30 毫秒进入请求。
- 预配置模型首次加载时捕获到可恢复的 React hydration 错误 `#418`；修改前的 `2928baf` 经独立构建与单次加载也复现同一错误。页面随后可正常操作，该既有问题仍待单独修复。
- **已发起真实服务测试，但尚未成功取得真实原生 GIF / SVG。** 使用 `https://api.aimountain.top/v1` 与 `gpt-image-2.6-sunburst`，首次 GIF、SVG 各提交一次；GIF 返回 HTTP 400：`GIF output is not enabled for this request.`，SVG 因网络连接失败而结束。旧错误未保留阶段，无法还原其具体断开位置。
- 补充诊断后，仅对 SVG 进行一次真实复测：请求 `output_format: svg`、`size: 1024x1024`、`n: 1`、`quality: high`、`background: opaque`、`stream: false`；约 21.5 秒后任务取得文件，但字节签名及 MIME 均为 PNG（1312×1199），原生 SVG 验证失败。应用保留 `.png` 原文件并明确显示格式不符警告，没有转换成 SVG，也没有自动重新提交生成。此次未复现网络中断，不能据此声称连接问题已根治。
- GIF 仍需服务商确认并开放当前模型、渠道或项目的 GIF preview 权限；SVG 需服务商确认 `output_format` 的透传与所选渠道的原生格式支持。公开文档没有可在客户端解除该 GIF 权限限制的参数，不能用更换参数或重复生成来承诺解决。
- 同一配置的只读 `GET /v1/models` 返回 HTTP 200 且列出该模型，仅证明认证和模型列表访问正常，不能证明原生输出已启用。该项目当前未显式透传 `moderation` 参数，真实请求使用服务端默认值。
- 本轮后端全量测试 178 项通过；新增检查覆盖生成/下载连接重置、HTTP 状态与 request-id、纯文本错误保留、凭据脱敏和失败不自动重试。生产页面在桌面与手机均用本地模拟错误验证了错误全文展示、阶段及网络码保留，无新增控制台错误；既有 React `#418` 仍可复现。模拟响应仅用于诊断流程验证，不代表指定真实服务支持原生输出。
